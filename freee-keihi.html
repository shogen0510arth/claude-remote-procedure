freee経費精算ツールの
使い方

毎月の経費精算を回すための手順書です。人がやることは2つだけ。領収書を部門フォルダに入れて、最後に freee で「申請」ボタンを押す。その間の取り込み・読み取り・申請行の作成・投入（下書きまで）・検算はツールがやります。

対象：freee-keihi 運用開始：2026年9月分 人の作業：2ステップ 課金：read のみ

目次

    ◎

    人がやることは2つだけ

    1
    領収書を部門フォルダに入れる
    2
    最後に freee で 「申請」ボタンを押す

    その間の取り込み・読み取り・申請行の作成・投入（下書きまで）・検算をツールがやります。

    ツールは絶対に申請ボタンを押さない

    ツールがやるのは下書きを作るところまでです。申請API（POST .../actions）は実装していません。最終確認と申請は必ず人が行います。

    1

    毎月の手順

    1-1. 領収書をフォルダに入れる

    領収書/ └── 2026年09月/ ← 領収書の日付月 ├── 01_ARTH/ ├── 02_WEAZER/ └── 03_土肥観光/
    • 第1階層は領収書の日付月。 9月フォルダに8月末の領収書が混じっていても、そのまま9月分として扱います。
    • 第2階層は部門。この1フォルダにつき申請が1件できます（01_ARTH → 9月分_ARTH）。
    • ファイルは JPEG・PNG・PDF。
    • _old や 元データ：… のようなフォルダは自動で無視されます。
    HEICは使えない

    HEIC は freee のOCRにも読み取りにも通りません。iPhoneは 設定 → カメラ → フォーマット → 「互換性優先」 にしておいてください。

    1-2. コマンドを実行する

    BASH
    cd ~/Developer/freee-keihi

    慣れるまでは1つずつ。 途中で止めて確認できます。

    BASH
    ./.venv/bin/keihi upload 2026-09        # ① 何が送られるか見る（freeeには何もしない）
./.venv/bin/keihi upload 2026-09 --yes  # ② ファイルボックスへ送る
./.venv/bin/keihi read   2026-09        # ③ 証憑を取得して読み取る（★課金あり）
./.venv/bin/keihi draft  2026-09        # ④ 申請行を組み立てる（freeeには何もしない）
open work/2026-09/review.md             # ⑤ ここで内容を確認する（人）
./.venv/bin/keihi submit 2026-09        # ⑥ 何が作られるか見る（作成しない）
./.venv/bin/keihi submit 2026-09 --yes  # ⑦ 下書きを作る
./.venv/bin/keihi verify 2026-09        # ⑧ 検算する

    2〜3か月まわして問題なければ、①〜⑧を1発でやる run に切り替えてよいです。

    BASH
    ./.venv/bin/keihi run 2026-09 --yes
    • run はどこかで失敗したらそこで止まり、後続を実行しません。
    • 要確認の行が残っていれば⑦の手前で止まります。
    呼び出し方は2通り

    ./.venv/bin/keihi の代わりに uv run keihi でも同じです。

    1-3. freee で確認して申請する

    work/2026-09/review.md の「要確認」を見ながら、freee の下書きを直して申請ボタンを押します。

    ここだけは人の仕事

    ツールは絶対に申請ボタンを押しません。 下書きを作るところまでしかやりません。

    1-4. 月の途中で領収書が増えたら

    もう一度同じコマンドを流すだけです。

    BASH
    ./.venv/bin/keihi run 2026-09 --yes
    • upload … 台帳にある分はスキップ。新しいファイルだけ送られる
    • read … 読み取り済みの分は使い回す。新しい証憑だけが読み取られる（＝課金も追加分だけ）
    • submit … 既に下書きに入っている行はスキップされる。二重計上しない
    追加分は「2つ目の申請」になる

    freeeの既存の下書きに行を足すことはAPIではできません（freeeの制約）。そのため追加分は「9月分_ARTH」という2つ目の申請として作られます。

    1つにまとめたいときは、freeeで先に下書きを削除してから run します。

    BASH
    # freeeの画面で 9月分_ARTH の下書きを削除 → その証憑が未使用に戻る
./.venv/bin/keihi run 2026-09 --yes    # 全部入りで作り直される

    削除せず2つに分かれたままでも、金額の合計は変わらないので運用上の問題はありません。

    コマンド一覧

    コマンドすることfreeeへの書き込み
    upload 2026-09何を送るか表示なし
    upload 2026-09 --yesファイルボックスへ取り込むあり
    read 2026-09証憑を取得して読み取るなし ★Claude API課金あり
    read 2026-09 --refreshキャッシュを無視して読み直すなし ★課金あり
    draft 2026-09申請行を組み立てるなし
    submit 2026-09何を作るか表示なし
    submit 2026-09 --yes下書きを作るあり（下書きまで）
    verify 2026-09下書きと突き合わせるなし
    run 2026-09 --yes上を順に全部あり

    補助のオプション

    • upload --section WEAZER … 1部門だけ処理する
    • submit --allow-review-pending … 要確認が残っていても投入する（既定は中断）

    4

    お金の話

    keihi read だけが課金されます。 領収書1枚ごとに Claude API を呼ぶためです。7月分35件で数百円程度でした。

    • 2回目以降の read はキャッシュを使うので無料（--refresh を付けなければAPIを呼びません）
    • draft のやり直しは何度でも無料。ルールを直して組み立て直すのは気軽にやってよいです
    • 読み取り自体をやり直したいときだけ --refresh を付けます
    5

    Claude Code をいつ使うか

    毎月の実行に Claude は要りません。 上のコマンドを打つだけでよいです。

    このセッションを維持する必要もありません。プロジェクトのフォルダで Claude Code を開けば CLAUDE.md が自動で読まれ、部門の対応・業務ルール・API制約はすべて引き継がれます。むしろ毎月新しいセッションを開くほうが正確です（長いセッションは途中の文脈が要約されて曖昧になります）。

    場面やり方
    いつもの月次ターミナルでコマンド。Claudeは不要
    要確認の直し方に迷うプロジェクトで Claude Code を開いて相談
    読み取りがおかしい同上。work/2026-09/files/ の該当ファイルを直接見て原因を調べられる
    ルールを増やす・変える同上。CLAUDE.md とコードとテストをまとめて直す

    そのまま貼れる文例は docs/PROMPTS.md の末尾にあります。慎重にいきたい月はこう頼みます。

    依頼文の例
    2026-09分の経費精算を通してください。
review.md ができたら、needs_review の行だけ私に見せて確認を取ってから submit に進んでください。

    安全のための仕組み

    ツールが勝手にやらないこと。

    • 申請ボタンは押さない。 申請API（POST .../actions）は実装していない
    • --yes が無ければ freee に書き込まない
    • 要確認が残っていたら投入を中断する
    • 使用済みの証憑はスキップする（1つの証憑は1つの取引にしか添付できない）
    • 作成直後の status が下書きでなければ即座に中断する
    • 同じ内容のファイルは二度送らない（SHA-256の台帳）
    • 読めない項目は空のまま人に返す。推測で埋めない
    8

    いまの制約（2026-08-12 時点）

    8-1. APIから作れない経費科目が10ある

    カスタム申請項目が設定されている経費科目は、freeeの仕様でAPIから申請を作れません。

    作れない経費科目

    消耗品費・新聞図書費・通信費・租税公課・採用教育費・外注費・修繕費・諸会費・宿泊仕入高・料飲仕入高

    該当する行は submit がスキップし、review.md に「web版freeeで作る」と出ます。その行だけ freee の画面で作ります。

    判定は毎回freeeに問い合わせている

    使えるかどうかは submit のたびに freee に問い合わせて判定しています。freee側で設定を直せば、ツールを直さなくても自動で使えるようになります（管理者に問い合わせ中）。

    8-2. 手作業でアップロードした領収書は部門が分からない

    部門は keihi upload が freee の備考に書き込む 2026年09月/01_ARTH から復元しています。freee の画面から直接ドラッグ＆ドロップすると、この情報が失われます。 必ず keihi upload 経由で入れてください。

    8-3. 7月分・8月分はこのツールで申請しない

    既に freee に手作業で入っており、証憑も別の申請に添付済みです。運用開始は9月分から。
